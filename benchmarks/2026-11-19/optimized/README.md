# 本地发号优化复测（2026-11-19）

后续对计数器本身做了缓存行隔离，见 [计数器缓存行优化](../counter-padding/README.md)。本报告使用的基准源码已保存为 [快照](idgen_bench_test.go.txt)。

六轮交替运行、九组场景中，当前版均快于公开 v0.1.0 和上一版。每组当前版的最慢一次也快于另外两版该组的最快一次。当前版仍为 **0 B/op、0 allocs/op**；公开版为 **32 B/op、2 allocs/op**。

## 改动与原因

上一版每次发号都会调用 ecache2.Get。相同实例争用同一把分片锁；不同实例虽有独立分片锁，但 ecache2 将 8 字节 Mutex 紧密放在一个切片中，M4 Pro 的缓存行为 128 字节，造成伪共享。仅隔离锁已显著改善不同实例场景，但共享实例的 4 核调用仍出现退化。

当前版给 IDGen 增加一个原子指针，复用当前秒的共享计数器 `[2]int64{时间戳, 序号}`。只有首次调用或换秒才查 ecache2；常用路径读取指针、检查秒值、原子递增序号。同一实例号（含 4 位掩码相同的多个生成器）仍从缓存取同一个计数器，回拨时复用历史计数器。没有 DCL、新接口、clockState 或额外历史 map。保留原有 clock 发布顺序和 Redis 分支。IDGen 增加一个指针大小的字段，首次使用后不得复制。

实际改动：[idgen.go](../../../idgen.go)、[与上一版的最小 diff](idgen-pointer-reuse.patch)。依赖仍为公开 ecache2 v0.1.0，没有 replace、overlay 或本地库替换；尚未发布此 idgen 优化。

## ecache2 的实验修复

[完整实验 diff](ecache2-padding.patch)仅增加 `cacheMutex{sync.Mutex; _ cpu.CacheLinePad}`，将分片锁切片和分配类型从 `[]sync.Mutex` 改为 `[]cacheMutex`。`cpu.CacheLinePad` 来自现有 x/sys 依赖，按架构设置大小；arm64 为 128 字节。没有增加接口或改变 Get/Put、LRU、过期行为。

以未复用指针的上一版 idgen 为固定输入，只隔离 ecache2 分片锁，三轮交替诊断的中位数如下，单位 ns/op：

| 不同实例 | 原始锁 | 隔离锁 |
| --- | ---: | ---: |
| 1 核 | 15.91 | 17.19 |
| 4 核 | 66.61 | 12.24 |
| 8 核 | 108.70 | 16.02 |

原始数据：[原始锁](lock-diagnostic-before.txt)、[隔离锁](lock-diagnostic-padded.txt)。实验使用公开 ecache2 v0.1.0 的独立临时副本，通过临时 modfile 引用，没有改模块缓存。这个实验验证了锁伪共享；它没有解决共享实例每次查缓存的锁竞争，因此最终方案直接移除常用路径的缓存访问，**没有修改正式 ecache2 库**。

## 复现

公开版使用 `git archive v0.1.0` 取出的源码。给公开版、上一版和当前版分别放入完全相同的 idgen_bench_test.go，保留各自 go.mod/go.sum；上一版可通过对当前 idgen.go 反向应用 idgen-pointer-reuse.patch 恢复。在各自目录编译：

```sh
GOTOOLCHAIN=go1.27.4 go test -mod=readonly -c -o /tmp/idgen-VARIANT.test
```

按 metadata.json 中记录的六种顺序运行，每次只执行一个二进制：

```sh
/tmp/idgen-VARIANT.test -test.run='^$' -test.bench='^BenchmarkNewLocal' -test.benchmem -test.benchtime=300ms -test.cpu=1,4,8 -test.count=1
```

## 验证与边界

- Go 1.27.4：共享实例并发唯一性、旧指针刷新、预初始化全部实例、跨 60 个秒键回拨复用计数器，以及已有本地发号/解析测试，10 轮 race 通过。
- Go 1.22.12：并发唯一性、旧指针刷新和回拨测试，外部链接 race 通过；链接器仍有既有 LC_DYSYMTAB 警告。
- Files 通过临时 modfile 引用当前 idgen，原有保护锁保留；并发 manifest 文件 ID 和刷新/重启持久化定向 race 回归通过。
- go vet、go mod verify、git diff --check 通过。原有 idgen_test.go 用户修改的 SHA-256 与本轮开始时一致。

基准衡量复用生成器的发号调用开销，会超过既有每秒 18 位序号容量，不能据此推算持续唯一 ID 的产出能力。零分配不包含生成器创建、缓存预分配和后台计数器准备的独立成本。未测试真实 Redis，也未测完整 Files 分享吞吐；本轮没有发布或更新下游正式依赖。
