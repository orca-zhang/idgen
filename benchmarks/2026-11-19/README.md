# 本地发号预初始化性能对比（2026-11-19）

后续已消除本报告中的并发退化，见 [优化复测与 ecache2 实验补丁](optimized/README.md)。以下保留最初结果。

与公开 v0.1.0（`5ff9a540a6ed6fa50e9c7ca62679f595ab391f23`）比较。新版保留秒级 `clock`，时钟协程在发布秒值前初始化 16 个实例的计数器；ecache2 使用 `[2]int64{秒, 实例号}` 键。没有 DCL、clockState、额外历史 map 或新增缓存接口。

本地分支查缓存后原子递增。缓存容量为 16 个分片、每片 256 条：每次准备 16 个实例时每片恰好增加一条，足以保留一分钟内 300 ms 更新的历史。过期使用 ecache2 原有逻辑。缺项时让出调度权并重试，处理进程暂停超过 TTL 后的恢复。

`clock` 参与缓存键和 ID 高位时间戳。若发号直接读系统时间，跨秒时可能先于预初始化，从而等待下一次 300 ms 更新。

## 方法与结果

Apple M4 Pro / macOS 26.6.2 / Go 1.27.4。两版使用完全相同的 [基准代码快照](optimized/idgen_bench_test.go.txt)，每个返回 ID 都参与 XOR 汇总；未使用 race 构建运行性能测试。CPU 设置为 1、4、8，各 300 ms，交替运行新旧版本共五组，下面列中位数和最小/最大值，单位 ns/op。

| 场景 | GOMAXPROCS | v0.1.0 中位数 [最小, 最大] | 新版中位数 [最小, 最大] | 旧/新调用成本 |
| --- | ---: | ---: | ---: | ---: |
| 串行 | 1 | 89.86 [85.88, 92.32] | 15.75 [15.23, 16.69] | 5.71× |
| 串行 | 4 | 75.27 [72.29, 76.01] | 15.74 [15.21, 16.03] | 4.78× |
| 串行 | 8 | 75.85 [73.18, 76.98] | 15.98 [15.31, 17.04] | 4.75× |
| 并发、同一实例号 | 1 | 90.26 [83.71, 91.82] | 16.79 [16.06, 17.38] | 5.38× |
| 并发、同一实例号 | 4 | 156.30 [133.40, 177.80] | 150.40 [142.40, 158.60] | 1.04× |
| 并发、同一实例号 | 8 | 201.60 [195.80, 206.00] | 140.50 [129.70, 150.00] | 1.43× |
| 并发、不同实例号 | 1 | 89.86 [85.09, 90.55] | 16.35 [15.79, 17.15] | 5.50× |
| 并发、不同实例号 | 4 | 58.32 [49.75, 67.93] | 71.02 [67.87, 77.94] | 0.82× |
| 并发、不同实例号 | 8 | 105.90 [100.80, 108.40] | 95.43 [80.08, 117.50] | 1.11× |

旧版均为 **32 B/op、2 allocs/op**，新版均为 **0 B/op、0 allocs/op**。此处为每次调用的摊销统计，不代表缓存预分配和后台准备没有成本。

收益集中在单核调用。4 核共享实例的差异很小；4 核不同实例中位耗时增加约 22%，8 核不同实例改善约 10%。不能把这版写成所有并发场景都更快，当前优化尚未发布。

## 数据与复现

原始输出：[旧版](baseline.txt)、[新版](candidate.txt)；环境、顺序与输入 SHA-256：[metadata.json](metadata.json)。

在两个独立目录中保留各自的 go.mod/go.sum，将相同的 idgen_bench_test.go 放到 v0.1.0 和候选版本，再分别编译：

```sh
GOTOOLCHAIN=go1.27.4 go test -mod=readonly -c -o /tmp/idgen-baseline.test
GOTOOLCHAIN=go1.27.4 go test -mod=readonly -c -o /tmp/idgen-candidate.test
```

各自在对应目录运行编译命令。使用以下参数交替运行两个二进制五次（第 1、3、5 组旧版先跑，第 2、4 组新版先跑）：

```sh
/tmp/idgen-baseline.test -test.run='^$' -test.bench='^BenchmarkNewLocal' -test.benchmem -test.benchtime=300ms -test.cpu=1,4,8 -test.count=1
/tmp/idgen-candidate.test -test.run='^$' -test.bench='^BenchmarkNewLocal' -test.benchmem -test.benchtime=300ms -test.cpu=1,4,8 -test.count=1
```

## 验证与边界

- 本地并发唯一性：同一生成器、相同实例号的多个生成器，以及 4 位实例号掩码，连续 10 轮 race 通过。
- 预初始化全部 16 个计数器、跨 60 个秒键后回拨复用同一个计数器，连续 10 轮 race 通过。
- Go 1.22.12 外部链接 race、go vet、go mod verify 和 git diff --check 通过。
- Files 使用临时 modfile 引用候选库：并发 manifest 文件 ID、刷新与重启持久化的定向 race 回归通过；未改动 Files 正式依赖。
- 原有 idgen_test.go 用户修改未改动。未测试真实 Redis，Redis 发号路径保持原有行为。

基准会超过既有每秒序号容量，仅衡量调用开销，不验证无限量发号唯一性，不能换算成持续唯一 ID 的产出能力。18 位序号容量和原有溢出行为没有改变。数据属于本机微基准，未衡量完整 Files 分享吞吐。
